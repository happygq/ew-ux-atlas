# EW-UX 建筑生成与交互设计基线 v0.2

> **状态：Design Baseline / 设计规则冻结，非实现或视觉验收通过**  
> **日期：2026-11-10**  
> **范围：Expandable Worlds 独立 EW-UX 建筑与建造体验研究（Huizhou Fantasy Architecture）**  
> **不涉及：WP1.1 Authority 协议修改、正式世界状态迁移、真实古建筑复原承诺**  
> **相较 v0.1：正式纳入庭院空间核 + 院内立面（内墙木构／石质墙脚／局部粉墙）+ 门窗自适应的联合设计要求。v0.1 原文保持不可改写。**

## 0. 一句话目标

让用户以尽可能少的 **Add / Remove / Recolor**（建造颜色选择）操作，逐步创造结构复杂、空间上真实、视觉上克制优雅的徽派幻想建筑与建筑群。建筑布局、空间连接、共享墙、屋顶、马头墙和材质由**确定性生成语法**推导，而不是要求用户手工摆放每一个构件。

核心约束：**复杂性出现在生成结果中，而非扩张为越来越多的建造命令。**

## 1. 决定分级与状态说明

- **D / 已确认设计原则：** 本轮讨论决定，作为后续实施的强制设计输入；不表示代码已经实现。
- **P / 研究原型：** 已有独立演示或候选实现，但不得替代系统集成及真实手机验收。
- **G / 开放验证关口：** 必须用操作回放、几何／拓扑测试和手机视觉检验后才能宣布完成。
- 如某一视觉候选与设计原则冲突，**改候选，不放松原则**。不得用某次测试数字代替其未覆盖的验收结论。

## 2. 用户操作与结构语义（D）

### 2.1 最小用户操作集

- **Add：** 向世界拓扑增加可建造单元；建造时以当前颜色身份（BuildColor）判定与新单元接触的既有单元是否形成内部连通。
- **Remove：** 移除指定单元；恢复仍存单元的外露边界，重新推导必要的共墙、收边与屋面，不得遗留悬空墙体或封闭死巷。
- **Recolor：** 改变颜色身份以控制后续 Add；**不追溯重写已经建立的室内连接关系**。改变建筑主题材质本身亦不得悄悄改变拓扑。
- Add/Remove 是基础**拓扑操作**；颜色选择／Recolor 是少量且必要的**结构表达手段**。不能把“仅 Add/Remove 无需任何颜色选择”与“三操作最小语法”混为同一个已证命题。

### 2.2 建造时语义与不可追溯性

- 新单元与既有单元**确实相邻**且当前建造颜色匹配时，按连接规则建立并**持久记录**内部连接；颜色不同则保留空间分隔边界。
- 已确认的边界状态属于独立结构事实（EdgeRelation），不能从**最终颜色分布**重新猜测。
- Add → Recolor → Add 可以得到不同于一次性同色 Add 的空间结构；这是能力，不是异常。
- 对多个同色邻居、拐角、跨楼层和历史断开边界的精确开口选择，需要专项测试，不能凭二维颜色相等直接全部打通。
- 建造操作顺序必须被确定性记录；但**重放确定性**应比较完整有效结构状态（包含持久边关系），不能仅比较最终占用格子与墙面颜色。

### 2.3 合并空间与结构支撑

- 连续相邻单元在已建立内部连通时，应表现为**可用的大空间**，而非多个独立小屋重复屋顶。
- 室内一体化与屋顶一体化属于相关但可分别检查的约束：连续大空间必须处理屋盖连续性、梁柱／跨度和上层承托；不能为了视觉上“无隔墙”就删除必要结构。
- 共享边只能有一个几何所有者；允许“实心公共隔墙”“有开口的连通边”“开放无隔墙”，视结构事实决定。

## 3. 空间相邻关系（D）

**ATTACHED ≠ CONNECTED。** 前者表示**建筑体量**贴邻／共享边界，后者表示**室内空间**实际连通。同一对邻接建筑可以共墙却不通室内；不得因为它们相邻，就一律自动并成一间房。

对于有效相邻建筑体量，建筑组团生成器将外部空间关系分成：

| 关系 | 语义 | 约束 |
| --- | --- | --- |
| `ATTACHED` | 贴邻 / 共用边界 | 不留下假缝；共享墙唯一生成或按真实连接消除 |
| `ALLEY` | 人行过道 / 巷道 | 连续、可达、有入口出口；宽度达到可通行的研究阈值 |
| `COURTYARD_GAP` | 庭院 / 明确退让 | 可读作庭院或开敞空间，而非碎小残余 |
| `RESIDUAL_SLIVER` | 无法使用的残余窄缝 | 禁止作为已完成的有效建筑关系 |

研究候选阈值：巷道净宽约 **≥1.10 m**，庭院退让约 **≥2.40 m**，仅用于第一轮视觉与几何实验，**不是防火、无障碍或建筑规范认证**；最终必须按场景与尺度调校。

**重要限制：**
1. 不能靠将所有房屋推来推去自动消除狭缝；新增操作不得擅自改变既存合法单元的用户授权位置。
2. 对最终状态的禁止残余窄缝要求，不应演变成“所有施工中间状态必须立刻完美”，否则会破坏复杂布局的 Add/Remove 可达性。允许明确、可继续构建或可回退的中间态。
3. 巷道通行必须按**连通网络**验证，而非只在俯视图上测一个局部宽度；院落与道路的封闭／外通情况需明确记录。
4. 既有世界状态与更新范围应由正式 Authority 约束；本独立研究只定义候选 UX 规则，不能绕过 Authority。

## 3A. 庭院／天井是一等空间对象（D：原则固定；生成合同待实验）

### CY-01　群体建筑必须支持“自生成庭院”

**EW-UX 的目标不是把庭院当成建筑之间剩余的空白，而是把庭院视为与 RoomRegion 同等重要的 `CourtyardRegion`。** 足够复杂的建筑群应能够借助 Add/Remove 的合法操作序列**自然围合出一个或多个真实可使用庭院**，不要求用户使用“Create Courtyard”新命令。

- 基于三维占用／无顶空间，建立空域的连通与围合拓扑；既看封闭环，也看入口、敞廊、转角、上下楼层的实际开放界面；
- 不只是“检测洞”：判断空域**是否对天开放、是否可进入、服务哪些房间、是否留有可通行出口**；
- 房间连通图、院落连通图和室外巷道网络分别表达，并通过真实门洞与回廊连接；
- Add 部分围合 → Add 最后一侧 → 形成院；Remove 侧翼 → 从封闭天井变半开放院，或按判定规则恢复为开放空地。必须保证**可逆、可回放、可解释**；
- 中间建造阶段可以是未完成庭院或开放空地；不能把“群体最终应形成院落的审美目标”变成每一步都必须成环的硬性拒绝。

### CY-02　院落类型不是一个布尔值

`SKYWELL`（天井：采光/通风/排水的紧凑空间核）、`MAIN_COURT`（主庭院）、`SIDE_COURT`（侧院）、`OPEN_COURT`（与巷道或院门相通的半院）。类型由**开放天空、面积与比例、围合度、交通出口、相邻房间等级、上下界面**综合确定，不能仅凭“封闭环=true”或绝对面积判断。

- **天井：** 重点验证不被屋顶封死、屋面向院排水的集水/水沟、内立面采光与防潮；可小而精。
- **主庭院：** 以厅堂/居住区域为主，允许更明显的内外生活过渡；出入和建筑轴线可读。
- **侧院：** 功能更克制，连通附属室内空间及主院。
- **半院：** 能真实连通人行巷道或门洞，不是错误残余窄缝。

### CY-03　院落能够反向约束建筑组合

- 院的位置和尺寸由 Add/Remove 占用状态自然派生；**不得未经授权移动已经建造的房间**只为“优化构图”。
- 院落一旦形成，其边界即为门窗／内立面／回廊／屋顶排水与外墙高度分布的输入；建筑构图需维护相邻空间的采光、出入与适当的私密度。
- 同一组团中可出现多院、多进、院—巷—院的序列；**不是每个单间必须都有独立庭院**，而是组团生成语法必须支持合理的院落密度与层次。
- 内外空间组织的目标是**生活化的虚实相间**，而不是靠复制独立小房屋制造“有很多天井”的错觉。

### CY-04　庭院与外部间距判别严格分层

`COURTYARD_GAP` 是前阶段基于建筑间距的**外部退让分类**，**不自动等于正式 `CourtyardRegion`**：后者还要求可达性、围合、功能服务对象、天空开敞与边界角色。沿袭 ATTACHED / ALLEY / COURTYARD_GAP / RESIDUAL_SLIVER，同时明确何时将一块合法外部空地**升级为 CourtyardRegion**。

## 4. 马头墙、屋顶与建筑组团（D）

### 4.1 单体真实构造

- 马头墙是**山墙 / 防火墙的建筑构件**，不能作为与屋顶无关的独立展示板。
- 形态基于有效山墙宽度、屋脊及建筑角色，控制阶梯层数、水平檐长及压顶尺度；避免窄墙高密度短台阶导致的“三角齿形”。
- 墙面默认素白／近白；檐口、瓦、基础与排水均要真实收口。不得在同一实体位置重复墙面或重复支柱。

### 4.2 T / U 朝向与主次

- 同一 T 形主横向体量的两个对应端山墙应以**世界坐标下真实镜像**构成整体对称，不能仅复用同手性墙型造成扭曲；局部轴手性须按实际镜像关系验证。
- U 形开口两翼可以形成相向山墙，这是可能的院落几何结果，但**不是必须在所有 U 形设计里强调的唯一经典范式**。
- 开口两翼宜作为次要收口；主体或中轴厅堂更完整、更有分量。具体阶梯升幅、层数不是历史硬规则，而是审美候选。
- 局部多样性服从建筑的主次角色，不能“每面墙随机换形”；墙面装饰方向与轮廓镜像手性独立处理。

### 4.3 鳞次栉比来自组团，而非单墙

- 采用真实相邻屋体形成前／中／后三个以上可辨纵深层；通过共墙、巷道、院落、错列、主次高度和遮挡构成连续街巷。
- 允许不同墙头完整显露、局部显露或只见轮廓，但每个墙头必须有合法实体依托。
- 禁止把多排小房屋机械等距摆列，或利用“密集但不可通行的狭缝”假装真实村落层次。
- A 均衡层叠／B 主墙突出／C 密集鳞次是**测试构图样本**，不是用户建造时必须选择的高级命令。
- 高低错层、L/T/U 连续屋盖、谷线排水、共享墙及大室内都必须在连接处检验实体几何；禁止仅靠穿插屋顶来掩盖错误。

## 4A. 院内立面与门窗必须联合研究（D：用户需求已确定；构型待验收）

### IW-01　不能只有“屋外粉墙”：朝院内墙须单独建模

现实徽州民居可同时出现**外部砖墙与粉壁、内部木柱木梁、木板壁或泥灰填充、格窗隔扇、木门、敞廊以及石质台基/墙脚、踏步/铺地**。因此，系统不应对所有面对庭院的墙统一刷木色，也不能把木制墙体视为无结构的贴皮。部分庭院立面保留白墙、砖石墙或木白混合，应当是明确的、受控的类型选择。

院内立面家族建议：

| 语法类型（候选） | 木构与围护 | 与院落的联系 | 适合角色 |
| --- | --- | --- | --- |
| `TIMBER_SCREEN` | 柱梁＋木格隔扇／板壁＋门窗 | 可开合、通透度较高 | 主厅、院内生活立面 |
| `TIMBER_STONE_BASE` | 木柱框架＋木板／格扇＋青灰石质台基、踢脚或墙裙 | 稳重、耐久、可配坐槛 | 一般院内界面与回廊 |
| `PLASTER_TIMBER_HYBRID` | 粉白填充墙＋露出木构＋少量木窗 | 内外呼应、材料均衡 | 侧院、次要厢房 |
| `PLASTER_COURT_WALL` | 与外墙近似的白粉墙／砖质墙体、克制开口 | 私密、封闭感强 | 边界墙、防火/服务性内立面 |

**石材位置以台基、墙脚、局部墙裙、踏步和铺地为研究起点**，而不是规定“所有内墙都是木与石大面积交替拼贴”。负重木构、隔扇及填充墙的层级必须独立，严禁用装饰性假柱代替必要真实支撑。

### IW-02　内立面、开口和院落一同求解

先计算 `CourtyardRegion` 和 `WallRole`（面院／临街／共享墙／厅堂／天井／封火墙等），再为该连续墙段确定：

1. 房间的功能等级、院落尺度、主次轴线与入口；
2. 木柱／梁／台基／石质墙脚所允许的**真实开间**；
3. 木板、粉墙、隔扇、格窗、实门和敞廊的虚实比例；
4. 通行、采光、遮挡、防潮与院内活动关系；
5. 真实门窗孔洞、窗棂门扇和立面装饰细节；
6. 屋檐、檐沟、院内铺地、水沟和门槛的交界收口。

不要把“木立面”“窗”“门”“庭院”拆成四个各自随机摆放的子系统。DW 应与 IW 同步设计、同期进行早期视觉验收，**不得等门窗模型完成后才给墙换木材质**。

### IW-03　墙长、房间合并、层高变化时要真正重组

- Add 扩大一个连续室内区 → 重新划分受影响的**连续院内立面与柱间**；允许新增窗扇、减少开口、增加隔扇、变为敞廊，尺寸受规则约束；
- Remove 导致边界外露或庭院开放 → 重算墙体角色与材料分区、门窗实际孔洞及院内踏步，不保留幽灵窗或两套重叠墙；
- 层高／地面标高变化 → 门窗竖向对齐墙身、楼板与坐槛，窗扇不能穿梁、悬于庭院或遮挡主通道；
- 新的共享墙不等于室内连通；禁把院内敞廊错误贯穿邻居私室；防火山墙开口受限制；
- 结构跨度与门窗数量之间应采取**重排优先、受限微调、禁止整体拉伸木棂纹样**的原则；
- 对不受 Add/Remove 影响的院内立面，应保持稳定的 WallSegmentId / OpeningId、开口位置和材质变化。

### IW-04　审美一致性：外白内木、局部内白、青灰石脚，统一青瓦

建议采用“**墙体主色克制、木构细节丰富、石质只做份量感与耐久性**”的视觉层次。木构候选为深烟棕、温润旧木褐、近墨色木梁；石质候选为青灰／浅灰；局部白墙沿用宣纸四色的淡暖色族。颜色仅是视觉研究候选，不能改变 BuildColor 结构身份。**实际颜色与材料覆盖比例须经过三角网格和手机光照下的视觉验收**，不能只凭 HEX 样本冻结。

## 5. 世界指南针与建筑朝向（D）

- **正式中文习惯用语：坐北朝南**，即主入口／主要朝向通常朝南，非“坐南朝北”。
- 研究坐标约定：`+Z` 为虚拟世界北，`+X` 为东，`−Z` 为南。朝向角以正北为 **0°**，顺时针增加。
- 建造布局推荐：**正南 180°** 为默认；**东南 135°**、**西南 225°** 为常用候选；保留任意朝向自由度，不以偏离正南拒绝 Add/Remove。
- **指南针默认显示**、固定于世界坐标系，镜头绕转时正确表现相对朝向；不能将镜头方向、屋脊轴线、建筑真正入口朝向混为一谈。
- 当前指南针仅为**虚拟世界规划指引**，并非手机磁力计/GPS 提供的实测地理北向。
- 如需要系统以后自动给出“朝向是否合理”的评价，须先存在可信的建筑入口/主立面语义；不应从屋顶方向强行猜测。
- 古徽州建筑存在丰富的场地、风水与地形朝向差异；南向是北半球常见**软性偏好**，不是普适历史律令。

## 6. 克制配色与结构颜色解耦（D：方向已定，色值为候选）

**首选方案：Quiet Huizhou / 宣纸四色 v0.1**

| 建造色身份（暂定） | 材质色 HEX（视觉研究候选） | 视觉角色 |
| --- | --- | --- |
| 宣纸白 | `#EEEAE0` | 主要粉墙 |
| 雾青 | `#D8E4DF` | 低饱和冷色辅墙 |
| 暖绢 | `#EBDCCA` | 低饱和暖色辅墙 |
| 远山灰 | `#D6DCE0` | 灰白次要体量 |

- 屋顶统一以深灰黛瓦为视觉家族核心；木构、砖石与压顶保持克制，避免房屋变成显著分彩色的积木。
- **BuildColor** 是建造时可识别的结构标签；**AppearanceTheme** 是视觉材质映射。二者不能彼此代替，更不能让换主题／换材质重写室内结构。
- 建造视图可以用更鲜明的边界线、标记、编号／纹理帮助区分四种颜色；建筑视图可以更统一、更接近粉墙黛瓦。
- 建造视图必须考虑低对比屏幕与色觉差异：不能**只靠**四种极浅颜色判断结构关系。触摸选中、预览即将打通的边界和实际已打通的边界应有显式反馈。
- 以上 HEX 值**未获真机建筑审美验收**，下一轮可调整材质色，但不改 BuildColor 的结构身份。

## 7. 最重要的架构隔离（D）

```text
User Actions: Add / Remove / Recolor (+ current BuildColor)
                 │
                 ▼
Persistent Spatial Topology + Construction History
(occupancy, boundary facts, adjacency, room connectivity)
                 │
                 ▼
Room & Courtyard Topology
(RoomRegion, CourtyardRegion, Circulation Graph, Alley / Open Court)
                 │
                 ▼
Structural & Massing Assembly
(unique shared walls, real column bays, height transitions, roof groups)
                 │
                 ▼
Courtyard-Facing Facade & Openings
(inner timber frame / stone base / partial plaster,
 true doors, windows, screens, galleries, drainage)
                 │
                 ▼
Streetscape & Appearance
(gables, boundary walls, layered silhouettes,
 Quiet Palette, construction highlights, world compass)
```

约束：
- 视觉颜色、相机、指南针、观察模式不改变已存占用、建造顺序、结构边状态。
- 外部布局关系不替代室内连接关系。
- 与真实 Authority 语义对接之前，不把研究生成器的布局参数、样本种子或人工摆好的 A/B/C 模板冒充真实 Add/Remove 构造历史。
- 正式实现必须遵守 Authority 事务和证据边界；此文只定义 **UX 目标行为**。

## 9. 下一阶段：Construction Semantics & Quiet Palette Gate（G）

**优先级高于增加新的马头墙数量及更复杂的村落宏观造型。**

### 9.1 第一轮固定试验（建议命名 CS-QP v0.1）

1. **CS-01 大空间**：从空场景连续 Add ≥4 个同色紧邻单元，形成真正连通的室内空间，屋面与支撑不出现无意义分段。
2. **CS-02 贴邻不连通**：不同颜色单元贴邻形成唯一公共隔墙，内室保持独立；一堵共墙不能被绘制两次。
3. **CS-03 历史与改色**：Add → Recolor → Add；已建立连接不受追溯影响，新连接按改色后的建造身份判断。
4. **CS-04 Remove 修复**：从大空间或共墙组团删去中间与端部单元，剩余外墙、马头墙、屋顶与通行关系合法；恢复或新建不产生幽灵连接。
5. **CS-05 巷道可达**：通过合法 Add/Remove 步骤形成共墙—巷道—庭院复合组团；验证无完成态残余窄缝与死胡同误判，并容许合法中间态。
6. **CS-06 复杂组团可达**：不直接调用排布模板，在同一操作语法下依次建出 A/B/C 类型及至少一例跨层复杂布局。若某目标不可达，给出最小失败操作序列。
7. **CS-07 双视图审美**：同一结构切换“建造视图/建筑视图”，四个 BuildColor 必须可辨；建筑视图应整体仍是粉墙黛瓦，留待用户手机审美验收。
8. **CS-08 方向独立**：修改指南针偏好、转动相机、切换视图，不得改变拓扑哈希或既有入口事实。

### 9.2 强制验收证据

- 可回放的操作序列、每一步单元/边/房间身份和空间关系快照；
- 几何与拓扑专项测试：重复墙、占用冲突、残余窄缝、无效通道、屋顶连续性、重放一致性；
- 至少两种移动端视角及两个视觉层（建造／建筑）的截图或可交互预览；
- 保留已验收 G203 与此前研究候选版本的原始文件，不覆盖；
- 标明测试覆盖范围，禁止把单一局部通过宣称为“任意复杂结构已证明”。

### 9.3 通过后的实施顺序

`CS-QP 基础语义 → CY-IW-DW 联合开口与内立面验证 → 复杂房间/院落/街巷真实操作回放 → 原 UX-G205 / G205-B 高低错层 → G206 泛化几何与性能验证 → 与 R2.3/Authority 正式接口的单独设计评审`。

## 9A. 下一轮优先级升级：CS–CY–IW–DW 联合试验（G）

在 CS-QP v0.1 的已定测试之上，**不得跳过庭院与内立面，独立宣告“复杂房间已完成”**。新增如下强制回放：

| 验证 | 从空场景的操作序列（只允许基础操作） | 验收 |
| --- | --- | --- |
| CY-01 环形成院 | Add 相邻房屋 → 逐步围合 → 形成回字空域 | 自动识别 CourtyardRegion；天空敞开、院可达，未封闭阶段正确保持候选状态 |
| CY-02 开环转半院 | 在 CY-01 上 Remove 一侧 | 庭院类型改变、开口朝巷道；门窗/内立面/屋檐同步重组 |
| CY-03 多院多进 | 连续 Add 大空间＋侧厢＋二进小天井 | 不依赖预置模板，庭院、内室、巷道服务关系正确且可回放 |
| IW-01 内墙材料 | 同一个院的主厅、厢房、服务墙 | 木格隔扇／木石墙脚／局部白墙有明确位置逻辑与层级 |
| IW-02 长墙重排 | 1→2→4 个同色 Add 单元；再 Remove 一端 | 柱间/木墙/门窗合理重排；禁止大比例拉伸格扇 |
| DW-01 院内实门 | 创建可达院与主厅，连续 Add 成室 | 门洞与通行图一致；石质门槛、铺地与木框实际收口 |
| DW-02 墙体角色变化 | 外墙 → 内院墙 → 共享墙 → 外露墙 | 真实孔洞、立面材质、开口密度重推导，无重复墙／假窗 |
| DW-03 高低与三视角 | 高低错层 Add/Remove，切换低视角／俯视／室内剖视 | 不穿楼板屋檐、不开悬空门；院内细节可见而整体街巷仍克制 |

**可证明结果：** 原始建造操作日志、每一步 Room/Courtyard/WallRole/Opening 的状态快照、确定性网格、独立拓扑／渲染测试、真实手机查看三个视角（街巷外观、庭院内立面、去屋顶室内），以及与用户参考的鳞次栉比美学对照。

**分阶段顺序：**

1. **CS-CY-IW-DW / R1：** 结构与院落语义冻结（RoomRegion、CourtyardRegion、WallRole、Entry/Passage）、可回放建造序列；
2. **R2：** 连续内墙柱网、木石／白墙的**几何构造**与真实门窗孔洞共同验证；
3. **R3：** 庭院屋面排水、院—室—巷连续可达、大小空间/高低层的联动和建筑群整体构图；
4. **R4：** 宣纸四色＋木石材料＋院落生活氛围的手机视觉验收；再开展完整高低错层、性能和正式 DTO 对接评审。

## 10. 版本管理与变更原则

- 本文件为 **v0.2 设计基线**，在 v0.1 保留的基础上整合围合庭院与院内立面/门窗联动的用户设计原则。**不是产品验收签字**。
- 后续如果确定颜色逻辑必须改变、朝向约束必须强化、合法空间关系必须增加，先给出**不兼容性说明、迁移与回放影响、验收反例**，经用户确认后发布新版本。
- 不触碰 `happygq/Expandable-Worlds` 的 WP1.1／Authority 正式代码；独立 EW-UX 研究仓库维护公开实验与设计文档。

---
**冻结摘要：** 庭院／天井是一等空间对象；院内立面与门窗同期研究（木构、石脚与部分粉墙）；房间—庭院—门窗—院墙共同构成整体；最小操作 + 建造历史；贴邻 ≠ 室内连通；无残余窄缝但允许合法施工中间态；山墙真实依附与组团层叠；坐北朝南软偏好与默认世界指南针；宣纸四色为候选；结构语义／空间关系／建筑几何／视觉材质分层；先以真实 Add/Remove/Recolor 回放证明复杂建筑可达性。
