# EW-UX · R2-V Stage 2 · 三维空域与垂直交通候选验证记录 v0.1

> **状态：CANDIDATE；G-V1 OPEN；R2-A 未冻结。** 2026-11-10。此增量记录不改写已冻结 EW-UX 建筑设计基线 v0.1/v0.2，也不修改单层 R1 已验收项目。代码位于独立 `g1-m2/r2-vertical-v02/`，上一轮 `r2-vertical-v01/` 保持原样。

## 验证结论与证据范围

1. **显式空域拓扑**：从三层占用状态建立完整空单元三维六邻接图，独立区分“直接望天（directSky）”和“虽被局部覆盖，但经侧方空域仍能与天空连通（atmosphericStatus）”。这解决 v0.1 仅以同坐标上层占用判断的局限，**但不代表存在真实屋面或可通行廊道**。
2. **V02 露天／封闭／重开**：上层桥接占用前，底层庭院连到天空；中心覆盖后，底层封闭空格与天空断连；移除后重新连到天空。它是占用拓扑真实性质，不是结构屋面验证。
3. **V07 局部覆盖**：一层 3×4 围合出两个相邻内院空格，二层覆盖其中一个。被覆盖的那格不能直望天空，但仍通过另一格的空气通道通天；不能误判为密闭空间。
4. **层间界面**：上下两个已建单元即使重叠，层间 slab interface 仍标为 `SOLID_UNOPENED`、`passable=false`。在几何开孔真实发生前，不增加实际楼梯通道。
5. **V05 支撑替换**：在两侧下层支撑单元有效时，删除中间原直接承托可将同一个上层单元的候选承托从 `DIRECT` 改为 `ONE_BAY_BRIDGE_EW`。保留上层稳定单元 ID；拒绝继续删除唯一剩余的必需端点；重新添加中间单元后回到 `DIRECT`。**本结果不证明桥接荷载安全**。
6. **V06 楼梯候选**：两层存在重叠的、各层局部 2×2 OPEN 连通区时，生成可重复的 `ELIGIBLE_UNREALIZED` 方案；Recolor 不追溯改旧 OPEN 边，所以候选仍在；Remove 破坏必要足迹时，候选撤回。**候选不是用户新命令、不是已实现楼梯，也不意味着有通行许可。**
7. **原 V01–V04**：直接复用第一轮已测试的语义源码与固定操作，不修改任何原始操作序列。已获用户认可的 V04 步骤解释页面仍在 v0.1 路径，不被替换。

## 不能关闭 G-V1 的三项阻断

**B1 · 垂直通行的实际来源尚未冻结。** Add/Recolor/Remove + 楼层坐标不能唯一表达住户希望在哪里设置楼梯。当前算法仅自动提出满足局部 2×2 约束的 *candidate*。需要独立确认自动规划规则如何结合建筑身份、主次轴线、私密性、上下层房间等级，并能否在不增加用户复杂命令的情况下稳定解决多层通行。

**B2 · 结构接口没有实际开孔与认证。** 当前 `SOLID_UNOPENED` 不可通行，开口的净高、楼梯踏步、梁/柱净空、受力与真实碰撞均未检查。G-V1 的最终通过需有经过评审的抽象 SlabOpening/StairConnection 正负语义合同；R3-V 另需实体几何证据。仅有候选不能作为“已可通行”。

**B3 · 承托桥接仅是未验算的研究假设。** `ONE_BAY_BRIDGE` 的存在只能说明两端下层占用；真实桥梁跨度和可用承托必须经过几何与规则认证，否则生产路线应该拒绝删除或采用其他合法承托方案。当前展示不能当作结构工程建议。
