# EW-UX 门窗与动态开口系统：补充研究关口 v0.1

> **状态：OPEN RESEARCH GATE / 待设计与实验验收；不是已实现功能，也不修改已冻结的 Architectural Construction Baseline v0.1。**  
> 日期：2026-11-10。归属：EW-UX 独立研究。  
> 触发原因：用户指出此前已讨论的 Add/Remove、空间合并、共享墙、庭院与群组美学研究尚未验证**门窗、门洞、木格隔扇等构件随空间拓扑、面积、墙长和形体变化的正确重组与形变**。

## 1. 研究目标

仅使用既有 **Add / Remove / Recolor** 最小建造语法，系统能够随空间变化自动生成合理的：

- 对外主入口（门楼、门罩、门扇与槛）；
- 庭院／天井立面（隔扇、木格窗、门窗组合、开放式敞廊）；
- 室内通行口、公共隔墙、可开闭屏门；
- 少量高位小窗、侧墙采光和通风洞口；
- 与墙体柱网、梁、檐口、台基和马头墙无冲突的门窗实体开口。

**核心原则：门窗是墙体的真实拓扑开口与围护构造，不是贴图、悬浮道具，也不是单个单元房永恒不变的配件。**

## 2. 真实徽州建筑提供的风格启示

1. 徽州民居常见封闭外墙、少开外窗，历史上常以天井采光；窗的数量不能按建筑面积直接线性增加。
2. 面向天井、回廊、厅堂的界面更有条件采用木格窗、隔扇、开敞廊与组合门扇；内外立面疏密形成强烈的艺术反差。
3. 主入口与门楼有礼序和街巷识别功能，应根据主入口／院落轴线确定，而不是从屋脊方位推导。
4. 徽派幻想研究可在古典原型基础上适度改善可居住性、采光与尺度，但须明确这是艺术化研究，而非精确的历史复原或建筑法规认证。

## 3. 必须增加的语义层

从 Spatial Topology 到 Appearance 增加 **Facade / Openings Assembly（墙面角色与开口系统）**：

```text
Add / Remove / Recolor + Persistent Boundary State
  → Connected Room Region + Circulation Graph
  → Building Envelope & Wall Segments (shared / exterior / courtyard / alley / interior)
  → Structural Bays & Openable Intervals
  → Opening Planner (entrance / passage / windows / screen / gallery)
  → Wall Boolean/True Hole Geometry + Frame/Sill/Lintel/Lattice
  → Quiet Huizhou Materials & Detail LOD
```

核心数据建议：

- `WallSegmentId`: 稳定的真实连续墙段身份，不以“某一格单元房”的序号充当门窗唯一主人。
- `WallRole`: `OUTER` / `COURTYARD` / `STREET` / `SHARED_PARTITION` / `FIRE_GABLE` / `INTERIOR` / `GALLERY`。
- `RoomRegionId`, `EntranceIntent`, `CirculationPort`: 连通房间、主要入口意图和实际通行连接。
- `OpeningId`, `OpeningType`, `OpeningAnchor`, `BayIndex`, `OpeningConstraints`: 门窗在墙段上的语义锚定及可重新分配的构造约束。
- `PreservationPriority`: 稳定保留既有入口与重要开口，避免用户每 Add 一格就看到门窗无意义跳动。

以上只是建议研究 DTO，**非 WP1.1 Authority 或 R2.3 已冻结接口变更**。

## 4. 动态重组与形变规则（候选）

### DW-R01：先重算墙段角色，再排门窗

相邻房屋的外墙变成共享隔墙时，原外窗可能必须关闭／转为合法室内开口；当 Remove 使墙重新外露时，应重新出现合理的外立面，而不是复用不适用的内隔扇。正式防火墙不能自动开出普通大窗。

### DW-R02：门窗**重排优先于非比例拉伸**

墙面从一个单元延长到四个单元时，优先改变**柱网、开间数量、间距与门窗组合**。在受约束的范围内只调整局部构件尺度；禁止把一扇窗水平拉伸四倍，或把雕花比例严重扭曲。小幅增减墙长应有构型稳定带 / hysteresis，防止频繁换型。

### DW-R03：入口与通行是拓扑事实

主入口必须连接可达的街巷、前庭或明确路径；内部已连通的两个空间，不应为了“墙面整齐”新生成阻断通道的实心墙。门洞与连通边必须一致，真实开口贯穿墙体体积。

### DW-R04：尊重木构／柱网／楼层

新开口不得切断承载柱、重要梁、台基、檐口或马头墙压顶；窗洞上方需有对应结构边界与过梁／框构。大空间扩展时先重新分配结构跨距及屋面支撑，再允许扩大连续隔扇或改用多联门；支撑问题不能仅靠删柱解决。

### DW-R05：建筑群角色优先

- 临街外墙：主门+少量有节制的通风采光洞口；墙面留白。
- 庭院朝向：优先组合隔扇、格窗、敞廊，形成室内外交互界面。
- 共墙隔断：依据实际空间连通关系决定无开口／单门洞／通廊，不能仅按 BuildColor 外观生成窗。
- 马头封火墙：外观强调墙体连续性，普通窗门为受限例外，单独验证。
- 方向偏好与相机旋转：仅修改观看或规划提示时，不得改变门窗位置或间数。

### DW-R06：可预测的局部稳定性

相邻 Add/Remove 只重建受影响的房间、相邻墙段与支撑范围。无关墙的 OpeningId、锚点、尺寸和材质哈希保持稳定。即使重新计算局部墙段，也保留可继续使用的现有入口；必须迁移时给出确定性的候选与原因。

### DW-R07：色彩不干扰开口语义

BuildColor 用于增量建立室内连接；Quiet Palette 用于外观。Recolor 不追溯打开／封闭旧墙洞；改变外观主题不影响结构或门窗几何。建造视图应明确可见“实墙／门洞／连通边／窗洞”的不同状态。

## 5. 第一轮固定实验：DW v0.1

| 用例 | 操作序列 | 应观察到 |
| --- | --- | --- |
| DW-01 单间 | Add 1 | 合理入口／外立面、可归属的开口；无假窗 |
| DW-02 长向扩展 | 同色连续 Add 1→2→4 | 多开间门窗**重排**，而非把单窗拉长；结构间距可解释 |
| DW-03 室内合并 | 不同色贴邻 → Recolor → 新 Add | 已封闭隔墙不被追溯打通；新边的门洞遵守建造当时的连接事实 |
| DW-04 L / T / U 围合 | Add + Remove 构建内院 | 街巷外墙与院内立面在门窗密度、类型、材质上形成合理差异 |
| DW-05 共墙形成／解除 | Add 共墙邻房 → Remove 邻房 | 共享墙唯一；外窗转换／恢复合法；无悬空或重叠窗框 |
| DW-06 天井扩展 | Remove 中心单元/扩大院落 | 合法的新增院内立面隔扇、通行路径；可检测采光／开敞改变 |
| DW-07 高低错层 | 添加上层 / 部分 Remove | 门窗不穿屋顶、支撑、楼板，不生成悬空门槛 |
| DW-08 迭代稳定性 | 添加/移除无关单元；视角旋转；切建造/建筑视图 | 未受影响门窗 ID/位置不变；世界指南针操作对建筑几何零影响 |
| DW-09 极端墙长 | 窄墙/长墙、残留小墙段、转角 | 正确减少、拆分或放弃非必需窗，不扭曲窗棂，不进入柱网与边角禁区 |
| DW-10 可回放性 | 空场景起使用 Add/Remove/Recolor | 可重放得到相同房间拓扑、墙段、开口图与实际网格哈希 |

至少制作一组 **单间→四间大室内→L形→带天井的U形→Remove拆分**的全过程交互动画或逐步截图，并提供三个视角：临街外立面、庭院内立面、剖开屋顶的室内开口。

## 6. 质量与视觉验收关口

**硬性技术门槛：**
1. 每一个门窗均以真实穿孔的墙体拓扑表示；无贴墙假门、重复边、薄片穿模；
2. 无柱、梁、马头墙、檐口、屋面／台基碰撞；
3. 通过门洞的空间通行图与室内连通图一致；
4. 几何变形有上下限、柱间重排确定性、已存未受影响开口稳定；
5. Remove 后可重建且无幽灵门／悬空窗，整个操作历史可重放；
6. Node 几何与拓扑回归、手机实际 WebGL / 静态回退以及人工视觉验收，分别记录，不可相互冒充。

**审美门槛：** 粉墙黛瓦仍是主体；临街面克制留白，院内门窗更精致丰富；大空间门窗比例像完整建筑而不是复制的小屋串联；结合“宣纸四色”的建造视图仍能清楚识别室内连通。

## 7. 与既定实施计划的关系

建议将门窗系统标为 **DW-R1（墙面／开口语义设计）→ DW-R2（多开间重排与真实孔洞）→ DW-R3（真实 Add/Remove 回放与移动视觉 Gate）**。

- **先进行 DW-R1**：与 CS-QP v0.1 共用 RoomRegion、Boundary、WallRole、Circulation 的结构输入；不得先把门窗硬编码到原来的“单间房模板”。
- **CS-QP 验证过程中加入最小真实门洞和内隔墙**；否则声称“室内连通的大空间”仍不完整。
- **DW-R2 与宣纸四色视觉研究可并行开展**，但最终 **CS-QP + DW 联合验收**必须完成，才能冻结“复杂建筑可由最小操作连续生成”的整体能力。
- 不因 DW 工作包而覆盖 G203/G204 已验收或候选预览，也不修改正式 WP1.1 Authority。
